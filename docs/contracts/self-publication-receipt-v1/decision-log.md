## Production shapes inspected in the checkout

The checkout was `main` at `origin/main` and already had unrelated untracked plan files. They were left unchanged.

- `paulsha_cortex/coordinator/workflow.py:379-412,660-805`: `WorkflowRun` currently stores `planning_authority`, `planning_source_revision`, `pr_refs`, attempts, and gate refs; it has no `publication_receipts` field. Existing `GateEvidenceRef.to_dict()` is `{kind, ref}` plus optional `sha256` (`workflow.py:275-310`).
- `paulsha_cortex/coordinator/planning.py:74-75,351-402,1266-1275,1648-1805,2124-2135`: `_hash_payload` is ordinary SHA256 over compact sorted JSON; `_make_question` derives the `q-` ID from `{kind,prompt,source_refs}`; `_build_default_question_pack` uses the ordered missing kinds and same-kind-ref/accepted-ref fallback, then hashes the question rows for `qp-`; `validate_question_pack` requires exact equality with that deterministic report pack after normalization. `CompletenessReport.to_dict()` stores ordered assessments/missing kinds; peer evidence is a JSON object with scope, question pack, secondary evidence, primary integration, and artifact rows `{kind, ref, sha256}`. `manager.py:8154-8166` writes peer evidence as sorted compact JSON plus one trailing LF and hashes those exact bytes.
- `paulsha_cortex/coordinator/manager.py:3167-3233`: plan materialization selects the first accepted `kind="plan"` assessment, requires one output pattern, derives one canonical target, then writes via the planning transaction. It currently has a crash window before the registry update, which #979 addresses.
- `paulsha_cortex/coordinator/manager.py:7959-8170`: the brainstorm transaction journal has mutable `phase`, absolute paths, rollback content, modes, and `created_dirs`; an operation currently includes `kind,path,before_exists,before_hash,before_content,before_mode,after_hash,after_mode,created_dirs,mutation`. The proposal's operation is deliberately a bounded identity projection rather than a digest of that mutable recovery journal, as required by #992/#979.
- `paulsha_cortex/coordinator/work_bridge.py:606-628,2023-2047` and `github_delivery.py:886-980`: ship metadata is currently materialized as title/body/labels, `create_or_get_pull_request()` may adopt an existing PR, returns only an integer, and then `ensure_pr_metadata()` can PATCH/PUT remote metadata. That current path cannot supply #980's structured POST witness and is why the proposal treats the new PR contract as a future owner-owned seam.
- `paulsha_cortex/coordinator/registry.py:617-635,1881-2002`: registry create/update reconstructs `WorkflowRun` from known fields and `_persist()` writes the full registry. Existing `workflow.py` parsing cannot recover duplicate keys after `json.loads`; a raw-aware row decoder is needed for #1029's duplicate-key history case.

## Explicitly pending alignment

These are the unavoidable owner answers; they do not block delivering this bounded proposal, but they block calling the appendix accepted or starting #992 implementation:

1. #979 chooses/accepts exact brainstorm sidecar locations and the amount of source content retained in the pre-mutation snapshot.
2. #980/#994 accept the PR metadata retention/observation split in D10 or replace it with a single exact alternative.
3. #993 confirms how duplicate-key raw spans are preserved at its registry read boundary and that the invalid wrappers do not conflict with its typed append seam.
4. #992, #979, and #980 owners sign off the final event/publication basis key names, identity string rejection rules, and the independently generated values in `golden-vectors.json`.
5. #993/#994 confirm the PR object duplicate key used by the append conflict guard. The proposal and one literal conflict vector use `(repository, number)`; this is not a frozen cross-issue fact yet.
6. The receipt-ID-collision case is pending: a distinct valid SHA-256 collision cannot be computed as an executable golden vector. #993 still owns rejecting any such duplicate-ID value if it is ever presented.

Until those answers are recorded on the owner side, all vectors are proposed test fixtures only. The receipt-ID-collision vector remains explicitly pending; no item is marked accepted.
