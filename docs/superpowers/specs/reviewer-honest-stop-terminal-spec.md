# verify／review 卡誠實非通過 terminal 走明示停止落地規格

## Requirements

對應 [#874](https://github.com/hamanpaul/paulsha-cortex/issues/874)：verify／review 卡（reviewer persona）交出形狀合法、`status ∈ terminal_contract.NON_PASSING_STATUSES`（`failed`／`needs_human`）的 terminal——這是 #261 R1 明文允許、派工 prompt 也寫明「A non-passing terminal is a valid, expected outcome」的誠實結果——目前一律掉進 `terminalize_workflow_job()` 擲 `ValueError`，被包成 `terminalize-workflow-job-failed` 後再往上擲（periodic tick 又覆寫成 `resume-workflow-failed`），verifier／reviewer 寫的 `summary`／`details`／`reason`／`findings` 一個字都沒進 run，`evidence_refs` 為空。#717 的明示停止落地分支（`card-terminal-explicit-stop`）只認 plan／build；本票把同一語意延伸到 verify／review。

1. **R1 verify 明示停止的形狀判準**：新增 module-private 唯讀 predicate `_explicit_stop_gate_terminal(job) -> dict[str, object] | None`。以下條件全成立時回傳已解析的 envelope，否則回 `None`：job `workflow_evidence is None`、`status == "exited"`、`type(exit_code) is int and exit_code == 0`、`workflow_phase == "verify"`；`_extract_terminal_json(job["log_path"])` 不擲 `ValueError`；envelope key set 恰為 `{"schema_version", "kind", "status", "summary", "details", "reports"}`；`type(schema_version) is int and schema_version == 1`；`kind == "workflow-verification-result"`；`status ∈ NON_PASSING_STATUSES`；`summary` 是 strip 後非空的字串；`details` 是 dict，或 strip 後非空的字串；`reports` 是 list，且每個元素都是鍵集恰為 `{"path", "body"}`、兩個值都是 strip 後非空字串的 dict（`[42]`、缺 `body`、多鍵 → `None`）；`reports == []` 允許。report 的 manifest／governed root／大小檢查（`_inline_terminal_reports`）不套用，理由見 design D2。
2. **R2 review 明示停止的形狀判準**：同一個 predicate。job 條件與 R1 相同，但 `workflow_phase == "review"`；envelope key set 必須包含 `{"schema_version", "kind", "status", "reason", "findings", "reports"}`，除這六鍵外最多再多一個 `authority_hashes`；`type(schema_version) is int and schema_version == 1`；`kind == "workflow-review-result"`；`status ∈ NON_PASSING_STATUSES`；`reason` 是 strip 後非空的字串；`findings` 是 list，且每個元素都是 dict（finding schema 不驗）；`reports` 的判準與 R1 相同。`authority_hashes` 的內容不驗：非通過狀態不授予任何 authority，理由與 #717 放寬 candidate 相同。phase 與 kind 對不上（verify phase 交 review kind，或反過來）→ `None`。
3. **R3 落地 needs_human，不擲例外**：`resume_workflow_run` 撿到的 job 若被 R1／R2 認定，就不呼叫 `terminalize_workflow_job`，也不 raise，回傳 `{"run_id", "current_phase", "job_id", "reason", "declared_status", "terminal_diagnostics"}`。`reason` 依 phase 決定：verify → `verification-terminal-explicit-stop`，review → `review-terminal-explicit-stop`。run 經 `registry._manager_update_workflow_run` 加上 `needs_human` facet（既有 facets 保留、去重）、`gate_status="running"`；`needs_human_reason.reason` 與回傳 `reason` 相同，`source == "manager._poll_workflow_job:explicit-stop"`。periodic tick（`manager_daemon` 的 resume 迴圈）因此收不到例外，run 上的理由不會再被覆寫成 `resume-workflow-failed`。
4. **R4 病因原文與 evidence 指向**：`needs_human_reason.detail` 的形狀是 `f"{label} terminal 明示要求停止（status={declared_status}）：{model_text}"`，`label` 為 `verification`（verify）或 `review`（review）。`model_text` 是模型原文依序以 `key=value` 用 `；` 串起：verify 先 `summary`，再 `details` 的每一鍵（`details.<key>=<value>`；details 是字串時寫 `details=<text>`）；review 先 `reason`，再 `findings[<i>]=<canonical JSON>`。長度上限交給 `DiagnosticReason` 既有的 400 字截斷處理；verify 的 `summary` 與 review 的 `reason` 必須排在最前面。log_path 是非空字串時，`needs_human_reason.evidence_refs == [job["log_path"]]`；context 至少要有 `run_id`、`work_id`、`job_id`、`card`、`declared_status`。回傳的 `terminal_diagnostics` 是 `TerminalDiagnostics.as_dict()`：`model_diagnostics` 用同一組 key 帶出**不受 400 字截斷**的原文（仍受既有 `TERMINAL_MODEL_DIAGNOSTICS_LIMIT` 全體預算約束），`reason` 就是 `terminalize_workflow_job` 原本那句 `workflow {label} terminal reported non-passing status: {status}`，`authority_granted is False`。
5. **R5 不耗額度、不回派、不授權**：落地之後，`run.attempts` 不變（不會出現 `schema-mismatch:<card>` 或 provider retry 鍵）；本 run 不新增任何 job；該 job 的 `workflow_evidence` 仍是 `None`；`candidate_head`、`verified_head` 與每個 step 的 `gate_result` 都不變；不發佈任何 report。operator 顯式 `resume`（`operator_resume=True`）再撿到同一個 job 時，重新落同一個明示停止：同一個 reason、不派新 job、不 raise。重派出口維持既有的 `retry-card`（#569 force_new_card）與 `retry-build`；`workflow_status_entry(registry, run)["next_actions"]` 至少要有 `abandon` 與 `retry-card`。
6. **R6 reviewer sandbox 回收與 drift fail-closed**：寫入 needs_human 之前，先呼叫 `_discard_reviewer_sandbox(job, coordinator_root=coordinator_root, require_candidate_unchanged=True)` 回收 sandbox。它擲 `ValueError`（candidate checkout 被改動，或回收不完整）時，改落 `needs_human` reason `reviewer-candidate-drift`，detail 要有 declared status 與 `summarize_exception(exc)`，source 同 R3；回傳 `reason == "reviewer-candidate-drift"`。這條路一樣不 raise、不回派。
7. **R7 既有路徑不動**：`terminalize_workflow_job()` 對 verify／review `NON_PASSING_STATUSES` 的 `raise ValueError(...)` 保留，當作 fail-closed 守衛，既有測試的斷言不改。R1／R2 不認定的 verify／review terminal（缺 summary、多鍵、kind 錯、schema_version 不是 int 1、log 沒有 JSON…）維持現行的 `terminalize-workflow-job-failed`＋raise。plan／build 的 `_retryable_nonpassing_workflow_terminal`、`card-terminal-explicit-stop` 分支、`_malformed_workflow_card_terminal`、schema retry，以及 `_dispatch_workflow_card`／`resume_workflow_run` 的 retry 判準，全部逐字不變。
8. **R8 測試**：新增 `tests/test_reviewer_honest_stop_terminal.py`，走 RED→GREEN：(a) verify `needs_human`，agy 與 claude 各一份（#874 本文是 agy，第一則留言證明 claude 同樣命中）：agy 份的 job 用 agy executor identity，log 採 agy `--output-format json` 的單行 envelope `{"response": "<response 字串>"}`，response 字串是 agy 實機形狀（前置 fenced 文字，最後一行是帶 `toolAction`／`toolSummary` 的 structured output，同 `tests/test_agy_reviewer_json_schema_880.py::test_agy_structured_output_meta_keys_are_stripped_from_terminal_payload`）；claude 份用 claude executor identity，log 採 `{"type": "result", "result": "<terminal JSON 字串>"}` 形狀。兩份 envelope 的 `summary` 與 `details.host_preflight_status`／`details.sandbox_limitations` 都取 #874 本文引用的字串原樣（含本文裡的 `…`）當 fixture 值。oracle 是「fixture 值原樣出現在 detail 與 `model_diagnostics`」，不對照實機 log。兩份都經 periodic 路徑（`operator_resume=False`）的 `resume_workflow_run` → R3／R4 全部斷言成立；(b) verify `failed`、details 是字串、`reports == []` → 被認定，`model_diagnostics["details"]` 是原文；(c) review `failed`（#874 第二則留言的形狀：reason＋1 條 blocking finding），帶與不帶 `authority_hashes` 各一次 → `review-terminal-explicit-stop`；(d) R5 的全部不變量，加上第二次 operator resume 仍是同一個 reason、job 數不變；(e) `manager_daemon.build_periodic_tick_runner` 跑一個 tick → reason 不是 `resume-workflow-failed`；(f) `workflow_status_entry` 的 `next_actions ⊇ {"abandon", "retry-card"}`；(g) drift：monkeypatch `_discard_reviewer_sandbox` 擲 `ValueError` → `reviewer-candidate-drift`、不 raise；正常路徑則記錄到 `require_candidate_unchanged=True` 的呼叫；(h) 形狀反例（空 summary、多一鍵、`schema_version: True`、phase／kind 錯配、review 多出未知鍵、`reports: [42]`、report 列缺 `body`、review `findings: [42]`）→ predicate 回 `None`，resume 仍擲 `ValueError`；plan／build job 對新 predicate 回 `None`；verify／review envelope 對 `_retryable_nonpassing_workflow_terminal` 仍是 `False`。既有的 `tests/test_terminal_diagnostics_717.py`、`tests/test_terminal_result_contract.py`、`tests/test_agy_reviewer_json_schema_880.py`、`tests/test_review_authority_hashes_echo_922.py`、`tests/test_workflow_production_wiring.py` 原斷言全部保留。

## Boundary

Production 只改 `paulsha_cortex/coordinator/manager.py`：新增 `_explicit_stop_gate_terminal`、病因投影 helper，以及 `resume_workflow_run` 內緊接在 #717 `card-terminal-explicit-stop` 分支之後的落地分支。`terminalize_workflow_job`、`_retryable_nonpassing_workflow_terminal`、`_malformed_workflow_card_terminal`、`_dispatch_workflow_card`、`manager_daemon.py`、`registry.py`、`work_actions.py`、`claim.py`、`diagnostics.py`、`terminal_contract.py` 都不改。不做的事：

- 不做 verify／review 壞形狀 terminal 的自動重派與 per-card 熔斷（#578／#555）。
- 不把 review `status: failed` 轉成 GateEvaluation／`blocking-findings`（不綁 evidence、不寫 `gate_status="failed"`）。
- 不改 #750 `_prior_review_rejection` 讀 review envelope 的欄位對應。
- 不改 `work show` 的 item 層投影（`facets: ['degraded']`、`phase: None`）。理由：`work show` 經 `paulsha_cortex/monitor/work_api` 讀 Monitor 的 item 投影，`degraded` facet 由 `paulsha_cortex/monitor/lifecycle.py` 74–75 依 provider／correlation 診斷加上，與 workflow run 的 needs_human 路徑無關；改它等於多碰 `monitor` 模組。#874 要求的「`next_actions` 非空」在 run 層由 R5／R8(f) 的 `workflow_status_entry` 保證。
- 不改 operator 顯式 resume 對 reviewer 卡的重派語意：重派出口仍是 `retry-card`／`retry-build`。
- 不處理 #803（reviewer sandbox 缺 operator runtime）與 #807（agy fallback terminal 格式）的成因。
- 不新增 CLI。
