# Maintainer fallback 以 content-addressed v2 授權取代同 run/head 既有 v1 規格

## Requirements

對應 [#871](https://github.com/hamanpaul/paulsha-cortex/issues/871)：同一 `(run_id, head)` 已由 Copilot 路徑持久化 immutable `cortex-merge-authorization/v1`、merge 失敗後又落 `copilot-*` stop 時，operator 依官方 `review-attest` → `resume` 走 maintainer fallback，`_ship_with_maintainer_review` 產生的 `cortex-merge-authorization/v2` 被兩道檢查永久擋住：(1) `_authorization_record` 以固定檔名 `{run_id}-{head}.json` 撞上內容不同的 v1 → `merge authorization evidence conflict`；(2) 即使 (1) 放行，journal `ship["merge_authorization"]` 仍是 v1，`existing_authorization != authorization` → `persisted merge authorization differs from current gate evidence`。除 `abandon` 外沒有官方出口。

1. **R1 v2 授權走獨立 content-addressed 路徑**：`_authorization_record` 依 `payload["schema"]` 決定檔名——`cortex-merge-authorization/v1` 維持 legacy `{run_id}-{head}.json`（含既有衝突語意，逐字不變）；`cortex-merge-authorization/v2` 改為 `{run_id}-{head}-{digest}.json`（`digest` = `canonical_json_hash(payload)`，64 hex）；其他 schema → `ValueError("merge authorization identity malformed")`。同內容 v2 重寫冪等回同一路徑；同名但內容不同／symlink／可寫仍 `RuntimeError("merge authorization evidence conflict")`。寫 v2 永不讀寫、改名、刪除或 chmod 任何 v1 檔。
2. **R2 maintainer 路徑接受 journal 內同 run/head 的 v1 為 superseded audit**：`_ship_with_maintainer_review` 看到 `ship["merge_authorization"]` 的 payload schema 為 v1 時，不再把它當成「persisted 授權不一致」，而是在通過 R4 驗證後把它作為被取代的舊授權（superseded），另建新的 v2 並完成 merge。此規則在 `_ship_with_maintainer_review` 內不看 ship phase（`needs_human`／`copilot-*` 重入與 `merge-authorized` 帶 maintainer 參數兩條入口一體適用）；但 `merge-authorized` 入口必須先通過 `_ship_action` 既有前置檢查（`work_actions.py:5793-5809`，以 current authority、`terminal_reconciliation=False` 嚴格驗證 journal 授權），該檢查不改——journal v1 的 `authority_digest` 已落後 current 時仍在該處 `ValueError("ship merge-authorized state malformed")`，到不了本規則（見 Boundary）。v1 檔 bytes 與 mode（`0o444`）前後一致。
3. **R3 v2 綁定 superseded v1，journal 保留稽核**：有 superseded v1 時，v2 payload 多兩個欄位 `superseded_authorization_ref`（v1 wrapper 的 `path`）與 `superseded_authorization_hash`（v1 wrapper 的 `hash`），兩者一併進 v2 digest；journal `ship` 新增 `superseded_merge_authorization`（v1 wrapper 原樣 `{payload, hash, path}`），之後 phase 轉 `merged`／`done` 時隨 `{**ship}` 保留。沒有 superseded v1 時 v2 payload 形狀與現行逐字相同、journal 不寫此欄位。`_trusted_evidence_refs` 仍恰好 4 筆（`preflight`、`foreign_review`、`maintainer-review`、`merge_authorization`），`merge_authorization` 指向 v2 的 path／hash；v1 稽核經 v2 digest 以 content-addressed 鏈保留在 CompletionRecord 可追的證據裡。
4. **R4 fail-closed 不放寬**：superseded 候選（journal 的 `ship["merge_authorization"]` 或 `ship["superseded_merge_authorization"]`）必須 schema 為 v1，且通過 `_authorization_identity_matches(..., head=preflight.head, tree_hash=preflight.tree_hash, terminal_reconciliation=True)`（同 run_id／workflow_step_ids／repo／work_id／PR／change／todo_paths／head／tree_hash、檔案為非 symlink 的 immutable 檔且 wrapper 內容相符；只放寬 authority_digest 為任一 64 hex；此放寬只存在於 `_ship_with_maintainer_review` 的 superseded 驗證，`merge-authorized` 前置檢查不變）；若 `ship["merge_authorization"]` 為 v1 且 `ship["superseded_merge_authorization"]` 也存在，兩者必須相等。任一條不成立 → `RuntimeError("persisted merge authorization differs from current gate evidence")`，且**不得**寫出任何 v2 檔、不得呼叫 `merge_if_ready`。journal 已存在 v2 時，重算的 v2 payload 必須與既有 payload 完全相等，否則以同一訊息 raise、不寫新 v2 檔。`_validate_maintainer_review`（exact candidate、run、authority digest、bound gate ref hash）、foreign review hash、`evaluate_delivery_gate(review_kind="maintainer-review")` 與 PR HEAD 檢查全部維持現行。
5. **R5 replay 驗證 superseded 綁定**：`_authorization_identity_matches` 對 v2 接受兩種 key 集合——現行集合，或現行集合 ∪ `{superseded_authorization_ref, superseded_authorization_hash}`（兩者必須同時出現）；v1 key 集合不變。pair 存在時另須：ref 為絕對路徑、非 symlink、是檔案且 `st_mode & 0o222 == 0`；hash 為 64 hex；檔案 JSON 恰為 `{"payload","hash"}`、`hash == superseded_authorization_hash`、`canonical_json_hash(payload) == hash`；payload schema 為 v1，且 `run_id`／`repo`／`work_id`／`head`／`tree_hash` 與 v2 body 相同。任一不符 → False，因此 `merge-authorized`／`merged`／cached `done` replay 與 merge 例外後的 `_authorization_matches` 全部 fail-closed。
6. **R6 冪等與 Copilot 路徑不變**：同一 maintainer 輸入重跑得到相同 v2 path／hash，evidence 目錄內 `{run_id}-{head}-*.json` 只有一個；maintainer merge 第一次 raise（未 merge）後 `resume` 沿用同一 v2（journal 已是 v2＋`superseded_merge_authorization`）完成 merge。Copilot 路徑（`_ship_action` 產 v1 的 `_authorization_record` 呼叫與其後的 persisted 比對）行為、檔名與錯誤訊息逐字不變。

## Boundary

Production 只改 `paulsha_cortex/coordinator/work_actions.py`（`_merge_authorization_body`、`_authorization_record`、`_authorization_identity_matches`、`_ship_with_maintainer_review`，必要時新增同檔私有 helper）。不改 `completion.py`：CompletionRecord `trusted_evidence_refs` 維持恰好 4 筆、恰一種 review kind（`completion.py:180-209`），不新增第五種 `superseded_merge_authorization` kind——「closure trusted refs 同時列出 v1 與 v2」屬 durable CompletionRecord schema 變更、需同步 `completion.py`／`delivery.py`／`work_bridge.py`，另案處理；本票以 v2 digest 綁定 v1 ref／hash＋journal `superseded_merge_authorization` 保留稽核。不改 `delivery.py`（`ReviewLoop`、`evaluate_delivery_gate`、`verify_remote_closure`）、`work_bridge.py`、`manager.py`、CLI 與 `review-attest` payload；不改 Copilot 路徑的 v1 檔名與 persisted 比對；不處理反方向（journal 已是 v2、之後改走 Copilot 路徑）——維持現行 fail-closed；不放寬 `_ship_action` 的 `merge-authorized` 前置檢查（`work_actions.py:5793-5809` 以 current authority 嚴格驗證 journal 授權）：journal 停在 `merge-authorized`＋v1 且 WorkAuthority digest 已前進時，維持現行 `ValueError("ship merge-authorized state malformed")`（R7 (j) 護欄）——理由：`docs/unified-work-lifecycle.md` ship 段明定 merge-authorized 與 merge 前 gate 不使用 terminal authority 例外，放寬屬另一個安全決策；此阻擋與 v1／v2 檔名並存無關（Copilot 路徑在同一行同樣被擋）；#871 的實際路徑是 Copilot review timeout 後的 `needs_human`／`copilot-review-timeout` 重入，錯誤發生在 `_authorization_record`（代表已越過該檢查），本票已完整涵蓋，另案處理；不處理同一 review kind 內 gate evidence 漂移（`checks_hash`／`preflight_hash` 變化）造成的既有「persisted merge authorization differs」阻擋；不掃描磁碟上的 orphan v1 檔去補鏈（只認 journal 帶的授權）；不新增刪除或改寫任何 immutable evidence 的 action。
