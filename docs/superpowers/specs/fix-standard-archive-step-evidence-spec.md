# fix-standard 以 Manager archive job 證據判定 archive-applied 與 archive 結果 fail-closed 規格

## Requirements

對應 [#885](https://github.com/hamanpaul/paulsha-cortex/issues/885)：fix-standard combo（`paulsha_cortex/deck/data/combos/fix-standard.yaml`）編譯後 ship phase 只有 `policy-commit`，manifest 不含 `openspec-archive` step；`manager._manager_archive_applied(run)` 只認「恰好一筆 passed、identity 為 `cortex-manager`／`deterministic`／`cortex` 的 ship/`openspec-archive` step」，而 `registry._manager_reset_workflow_after_archive` 只標記**既有** step——fix-standard run 在 Manager archive commit 之後 archive-applied 恆為 False，post-archive `retry-build` 陷入 archive／重驗迴圈；`openspec archive -y` 回 `Aborted. No files were changed`（exit 0）時 Manager 仍把 `_ensure_openspec_change_scaffold` 補出的兩檔當 archive commit 收進。

1. **R1 archive-applied 單一判準、兩種 authority**：`manager._manager_archive_applied(run, *, registry=None)`：
   - `run.steps` 含 `phase == "ship"`、`card == "openspec-archive"` 的 step（combo 宣告了該卡，如 feature-oneshot）→ 判定與現行逐字相同（恰好一筆 passed 且 identity 相符），`registry` 不參與。
   - `run.steps` 不含該 step（combo 未宣告，如 fix-standard）且 `registry is None` → False（現行行為）。
   - 不含該 step 且有 `registry` → 以 job 證據判定：`registry.list_jobs()` 中同時滿足 `workflow_run_id == run.run_id`、`workflow_phase == "ship"`、`workflow_card == "openspec-archive"`、`persona == "manager"`、`executor == "cortex-manager"`、`model_id == "deterministic"`、`independence_domain == "cortex"`、`status == "exited"`、`exit_code == 0`、`workflow_evidence` 為 `kind == "ship"` 之 dict 的 job **恰好一筆**，且其 `subject_head`（符合 `verification.SAFE_SHA_RE`）等於 `run.candidate_head`，或經 `git -C <run.workspace_root> merge-base --is-ancestor <subject_head> <candidate_head>` 回 0 證實為其祖先 → True；零筆、多筆、subject／candidate 非合法 SHA、非祖先、git 失敗或 `OSError` → False。
   `work_bridge._manager_archive_applied` 簽名同步為 `(run, *, registry=None)` 並維持委派同一實作，不得另立第二套判定。

2. **R2 三個消費端帶 registry**：
   - `work_bridge.build_production_ship_validator` ship 段的 archive 守衛（現 `work_bridge.py:1920`）以 `registry=registry` 判定。
   - `manager._validated_ship_steps` 的 `matches_candidate` ancestry 分支（現 `manager.py:7862`）以 `registry=registry` 判定：fix-standard run 經 post-archive `retry-build` 後，final candidate 為 archive commit 後代時 `openspec-archive` 稽核通過；sibling／unrelated candidate 仍拒絕；`policy-commit` 仍要求 exact final candidate。
   - `work_actions._retry_build_action` 的 `archive_applied`（現 `work_actions.py:2466` 的 inline `any(...)`）改用同一實作並帶 `registry=workflow_registry`：fix-standard run 在 post-archive verify／review 失敗時 repair action 走 post-archive 分支（含 `Preserve the Manager-owned official OpenSpec archive` 與 `Do not recreate the active change`），不再出現 `make active OpenSpec tasks describe and complete only pre-archive work`。
   `_planning_artifact_relative_path_after_archive` 維持不帶 registry（見 Boundary）。

3. **R3 retry-build 派工前偵測並警告 active/archive 並存**：`_retry_build_action` 對 `len(authority.mapped_openspec) == 1` 的 run，在 `_manager_reset_workflow_for_retry_build` 前，以 `run.workspace_root` 上 `run.candidate_head` 的 Git tree（不得讀取來源 checkout 工作目錄、builder clone 或未提交檔案）檢查唯一 mapped change。若同時有 `openspec/changes/<change>/...` 與 `openspec/changes/archive/<entry>/...`，且 `<entry> == <change>` 或以 `-<change>` 結尾，retry-build 照常派 builder、不拒絕唯一修復出口，並在 action 回應新增 `warnings` 項目，列出 change 與全部 matching archive entries，說明 exact Candidate 含 active/archive 並存、須在下一次 review 前修正。無並存時回傳空 warning 清單；mapped change 數不是 1 時此 OpenSpec 檢查不適用，既有 retry-build 行為不變。若適用檢查無法讀取／解析 exact Candidate tree，raise 明確 `RuntimeError` 並在派工前停止；不可靜默將 inspection failure 當成無並存。

   **R3a post-archive 修復指示**：`_retry_build_action` 的 post-archive 分支保留全部既有句子（含 `Preserve the Manager-owned official OpenSpec archive`、`Do not recreate the active change`、`Commit or adopt a tested descendant Candidate` 子字串），另加一句英文指示：若 Candidate 已在 `openspec/changes/` 下（`openspec/changes/archive/` 以外）重建已封存 change 的 active 目錄，刪除該目錄、只保留官方 archive；句中必須含子字串 `re-created active change directory`。這是 archive-applied 已由 R1 證實時的修復指示，不取代 R3 的實際檢查及 operator warning。build-phase 與 pre-archive 分支其他文字不變。

4. **R4 archive 結果 fail-closed（Aborted）**：ship 段守衛呼叫 `openspec archive -y <change>` 後，既有 `returncode != 0` → `official OpenSpec archive failed` 不變；另外 stdout 或 stderr 含 `Aborted` → raise `RuntimeError`（訊息含 `official OpenSpec archive aborted`），不得呼叫 `_commit_archive_and_require_reverification`。

5. **R5 archive commit 前驗搬移後置條件**：`work_bridge._commit_archive_and_require_reverification` 在既有 allowlist 檢查之後、`git add` 之前驗：(a) `<worktree>/openspec/changes/<change>` 不是目錄；(b) 本次 `changed` 集合至少含一條 `openspec/changes/archive/<entry>/...` 路徑，且 `<entry>` 等於 `<change>` 或以 `-<change>` 結尾。任一不成立 → raise `RuntimeError`（訊息含 `official OpenSpec archive relocation missing`）；此時不 commit、不 harvest、不建 archive job、不呼叫 `_manager_reset_workflow_after_archive`（`candidate_head`、`current_phase`、來源樹 delivery branch 皆不變）。兩個呼叫端（ship 守衛、`archive-applied-needs-commit` 重入）同受此檢查。

6. **R6 ship 段 active/archive 並存 fail-closed backstop**：ship 段守衛在 archive-applied（R1、帶 registry）為 True、`<worktree>/openspec/changes/<change>` 是目錄、且 `<worktree>/openspec/changes/archive/` 下存在名稱等於 `<change>` 或以 `-<change>` 結尾的目錄時，raise `RuntimeError`（訊息含 `re-created active OpenSpec change`），不得再跑 `openspec archive`、不得進 `_ship_action`。archive-applied 為 True、active 存在但無對應 archive entry（既有 `archive-applied-needs-commit` 重入路徑）行為不變。R6 不取代 R3：reviewer 可在 ship 段前拒絕候選，因此 retry-build 自己必須完成並回報並存偵測。

7. **R7 測試**：新增 `tests/test_fix_standard_archive_step_evidence_885.py` RED→GREEN：
   - (a) predicate：fix-standard steps（無 `openspec-archive` step）＋registry 一筆 Manager archive job：subject == candidate → True；subject 為 candidate 祖先（真 git repo）→ True；sibling／unrelated → False；兩筆 → False；identity 或 evidence 不符（executor／model_id／independence_domain／persona／`workflow_evidence` 缺）→ False；`registry=None` → False；宣告 step（feature-oneshot）但 step 未 passed、registry 有 job → False（step 優先）。
   - (b) ship audit：fix-standard manifest steps＋archive job（archive commit）＋`policy-commit` job（final candidate＝archive commit 後代）→ `_validated_ship_steps` 通過；unrelated sibling candidate → raise `missing or ambiguous: openspec-archive`。
   - (c) retry-build：fix-standard run 停在 review needs_human、registry 有 subject == candidate 的 Manager archive job，exact candidate commit tree 同時有 active change 路徑與對應 archive entry → retry-build 仍受理（`reason == "candidate-repair-dispatched"`），回應 `warnings` 明列並存 change／archive entry；`subagent-build` action 含 `Preserve the Manager-owned official OpenSpec archive`、`Do not recreate the active change`、`re-created active change directory`，且不含 `pre-archive work`。
   - (d) retry-build tree snapshot：將 matching active/archive paths 只加入 exact candidate commit tree，並在來源 checkout 工作目錄放不同狀態 → 只按 commit tree 結果產生 warning；candidate tree 無並存時 warnings 為空，即使工作目錄有未提交檔案也不誤報。另以 `git ls-tree` 非零／無法解析輸出驗證明確 raise，且 `_manager_reset_workflow_for_retry_build` 未呼叫。
   - (e) Aborted：fix-standard 形狀 ship harness（`active_change=True, archived_change=False`）、archive runner 回 `returncode=0`，分別以 stdout 與 stderr 輸出 `Aborted. No files were changed.`、不搬檔 → 兩種情況 validator 都 raise 含 `official OpenSpec archive aborted`；`candidate_head` 不變、無 Manager archive job、來源樹 `feature/14-work` 不變。既有 `returncode != 0` 仍 fail，不能因輸出不含 Aborted 而前進。
   - (f) 未搬移：runner 回 0、stdout 空、不搬檔 → raise 含 `official OpenSpec archive relocation missing`，同 (e) 不變式。
   - (g) ship 並存 backstop：archive-applied（job 證據）＋candidate 樹同時有 active change 目錄與 `openspec/changes/archive/<entry>` → raise 含 `re-created active OpenSpec change`，runner 未收到 `openspec archive`。這項測試與 (c) 分別鎖住 retry-build 前置 warning 與 ship fail-closed 防線。
   既有 `tests/test_work_bridge.py`（含 `test_manager_archive_applied_semantics_match_between_manager_and_work_bridge`）、`tests/test_preflight_closeout_order.py`、`tests/test_ship_out_of_builder_clone_653.py`（含 `archive-applied-needs-commit` 重入）、`tests/test_ship_phase_harvest_649.py`、`tests/test_workflow_production_wiring.py`（含 `test_ship_audit_accepts_manager_archive_ancestor_after_retry_build`）、`tests/test_work_actions.py`（含兩條 retry-build archive authority 測試）、`tests/test_ship_lane_no_openspec_911.py` 原斷言保留。

## Boundary

Production 改 `paulsha_cortex/coordinator/manager.py`（`_manager_archive_applied` 加 registry 分支與 job 證據 helper、`_validated_ship_steps` 帶 registry）、`paulsha_cortex/coordinator/work_bridge.py`（wrapper 簽名、ship 守衛 Aborted／並存檢查、`_commit_archive_and_require_reverification` 後置條件）、`paulsha_cortex/coordinator/work_actions.py`（`_retry_build_action` 判定、exact candidate tree 並存偵測／warning 與 post-archive 文字）。不改 `registry.py`（不在 `_manager_reset_workflow_after_archive` 插入 step、不改 retry-build reset 的 ship authority 檢查）、不改 combo YAML／deck compile（fix-standard 不加 `openspec-archive` 卡）、不改 `_planning_artifact_relative_path_after_archive`（`work_bridge._artifact_rows` 雖把 `openspec/changes/<change>/{proposal,design,tasks}.md` 種進 planning authority，但 fix-standard post-archive 沒有消費端解析這些 ref：build 卡 declared inputs 只有 `docs/superpowers/plans/*<slug>*.md`、verify／review／`policy-commit` 無 inputs，`_validated_brainstorm_planning_authority` 只逐檔解析 brainstorm evidence 的 artifacts，而 planning runtime 的 destinations 在 `docs/superpowers/`）、不改 `work_actions._ship_action` 直接路徑的 archive 呼叫（非 workflow 的 `cortex work ship`；workflow 重入時其非搬移結果由 R5 攔下）、不拒絕已偵測到並存候選的 retry-build（它是修復出口，R3 派工並回報 warning，R6 作 ship 段 backstop）、不處理 pre-fix 已殘留兩筆 archive job 的 run（R1 判為 False、維持 fail-closed）。不處理 #876（archive gate changelog 判準）、#953（builder tests／docs 引用 active openspec 路徑、verifier 過時 ruling）、#887（merge 後 authority-restart 與本機 active／GitHub archived closure 衝突）、#808（tasks.md 未勾 preflight 項死結）、#847（PR 後 authority-restart）。
