# Recovery action 契約矩陣

本文件描述正式入口目前消費的 recovery 契約，不是第二套 recovery engine。action 名稱與各入口選擇集合由 `paulsha_cortex/recovery_action_contracts.py` 註冊；`tests/test_recovery_action_contract_conformance_843.py` 會雙向比對註冊資料、dispatcher、control contract、coordinator CLI、porcelain alias 與本矩陣。

矩陣的 13 列是 issue #843 的 13 個 work recovery 契約家族；`legacy-reviewer-retry` 列有兩個不同 work action，因此具體 work action 字串共 14 個。名稱相同的 `work-action` 與 `slice-action` 仍是不同契約，不能互相推定狀態或資源效果。

## 正式入口規則與相容性

- `cortex work <action>` 與 `cortex recover work <work_id> <action>` 都送 `work-action`；後者是有界 alias，只能選註冊的 11 個 action。
- `cortex slice-action` 與 `cortex recover slice` 都送 `slice-action`；這些 action 綁 slice、job、binding revision 與 slice evidence，不因此取得 WorkflowRun authority。
- 對 `retry-build`、`retry-verify`、`retry-review`、`recover-repair-commit`，coordinator work CLI 的 `--expected-candidate` 和 JSON payload 必須對同一個 exact SHA；若兩者衝突，提交前拒絕。舊版 payload-only 呼叫仍可用。
- recovery contract registry 只集中 action 名稱/入口，不改 registry schema、security gate、Trust Root、authorization、CAS 判準或 dispatch engine。`close-delivered` 是沒有 WorkflowRun 時建立 remote closure record 的另一契約；source link/start/ship/attestation 等註冊 work action 亦不屬 recovery matrix。
