Cortex：誰控制流程，一件工作如何完成？

Deck 定義流程；Persona 定義角色範圍；Manager 執行並判定推進；WorkflowRun 保存本次進度；Monitor 投影對外狀態。以下展開 feature-oneshot，並非所有 combo 的通用順序。

本頁的按鈕只追蹤文件中的工作路徑，不會派工、修改 registry 或合併 PR。文件通過驗證不代表實際 runtime 已通過端到端測試；分支版本仍待人類驗收。

核心權責路徑：箭頭是各自的動作，不表示所有元件都在執行同一份工作。

→ 提供角色契約，供 Card binding／phase 驗證
→ 提供已編譯的 persona-preserving WorkflowManifest
→ 建立 Run／更新 Step、attempt 與 evidence binding
→ 提供 Run／Step 進度給唯讀 provider
→ 聚合、保存 last-good 並投影四態

工作執行迴路：派工者與交回結果的執行器分開；儲存進度的 Registry 不派工。

→ 依當前 Step／Persona／Candidate 派出 Job
→ 交回 log／terminal payload／artifacts，等待驗證

01 · 各元件在哪一層，負責什麼

分層是閱讀分組，不宣稱部署／安全隔離邊界。每個元件只建立一個節點；下方關係列與流程引用同一組 ID。

03 · 角色契約，不是另一個進度控制器

Manager 角色
