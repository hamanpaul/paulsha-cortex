#841 service declaration drop-ins：改以 `systemctl show` 有效屬性定位 service artifact，涵蓋跨 systemd 搜尋目錄的 drop-in；解析有效 `Environment=`／`EnvironmentFiles=` 的 PythonPath，對不安全讀取、來源衝突或無法證明完整檔案範圍 fail-closed。probe 對外只保留安全投影，status／doctor 共用結果，並同步更新 loaded-runtime 文件與回歸測試。

對抗審查後修三個回歸：`cortex service status` 的 `loaded_runtime` 與 `cortex doctor` 現在以 probe 取得的有效環境（`environment_source`：env 前綴 ＞ `Environment=` ＞ `EnvironmentFiles=`，無法安全解析時該 service 標 `unknown`）決定 `PSC_COORDINATOR_ROOT`／`PSC_MONITOR_STATE_ROOT` 與 config revision，不再固定讀 `~/.agents/core/runtime/*.env`；只有 systemd 本身不可用的 direct 模式才退回既有 fallback（標示 `direct-fallback`），避免 drop-in 換 root 後對錯 state root／config。doctor 改與 service status 共用同一份有效環境判定（`service_declaration_projection`），不再各自從主 unit 檔重讀 `EnvironmentFile=`。`PYTHONPATH` 的套件定位改依 Python 實際匯入順序逐段搜尋，不再只看第一段，避免套件裝在後面段落時誤判 unknown。另加固 `probe_service_runtime`：`systemctl show` 回報的 `FragmentPath` 與這次探查的 home 不一致時視為不可信任，避免撞名的其他真實 unit 污染判定。

對抗審查第四輪再修四個回歸：（1）doctor 不再要求 manager／monitor 兩邊都是 `systemd-effective` 才採信——只要其中一邊確認有效就使用那一邊的值，另一邊無法判定時單獨標 unknown，不強制兩邊一起退回主 unit 檔粗略判定，確保與 `cortex service status` 對同一個 service 的結論一致；判定邏輯抽成 `runtime_attestation._environment_source_and_overlay`，doctor／service status 共用同一個函式。（2）（3）doctor 的 trusted systemd 路徑與 `cortex service status` 重建 `systemd-effective` 環境時，都不再以呼叫者殼層（`base_env`／`os.environ`）為底再覆蓋 unit 值——避免操作者跑 `PSC_MONITOR_CONFIG=... cortex doctor --json` 之類指令時，殼層裡 unit 未宣告的 `PSC_*` 污染 service 的 config／root 判定；殼層環境現在只用來描述 `operator_cli` 這次呼叫本身。（4）`service_declaration_projection()` 不再把 `PSC_*`／`PAULSHACLAW_*` 有效值放進對外輸出，改成 `environment_digest`（safe_environment_projection 後取 canonical SHA-256）＋既有的 `environment_source`；真正的值改由新的 `service_environment_overlay()`／`probe_service_runtime()` 的 `_environment_overlay` 內部鍵取得，只供程序內部重建 root／config，並在所有會整包序列化的呼叫端（`cortex service status`、`cortex inspect service`）明確剔除，不再序列化進 JSON 輸出。

對抗審查第五輪再修三個回歸：（1）新增的 doctor 測試過去只呼叫 `_load_bootstrap_environment()`，沒有跑過 `run_doctor()`／`loaded-runtime` probe，manager systemd-effective、monitor unavailable 時 doctor 是否逐 service 判定完全沒被驗到；新增兩個 `run_doctor()` 全流程測試補上這個缺口（manager drop-in／monitor unavailable 的跨 service 污染、monitor `PYTHONPATH` 衝突）。（2）`doctor._loaded_runtime_probe()` 過去用同一份合併過的 `environment` 算 manager／monitor 兩邊的 root／config，沒有用 `probe_service_runtime()` 的 per-service `_environment_overlay`——manager effective、monitor unavailable 時會誤拿 manager 的環境去比對 monitor，與 `cortex service status` 不一致。現在改成逐 service 呼叫新抽出的共用判定函式 `runtime_attestation.declared_service_environment()`／`unknown_runtime_report()`（`cortex service status` 的 `_loaded_runtime_payload()` 也改用同一組函式），manager／monitor 各自用自己的有效環境算 root，任一邊 direct-fallback 時只讀那個 service 自己的 `EnvironmentFile=`，不沿用另一邊的值。（3）`_load_bootstrap_environment()` 過去在 manager 為 `systemd-effective` 時直接 return，後面判定 monitor `unknown`（例如 `Environment=`／`EnvironmentFiles=` PYTHONPATH 衝突）的 guard 永遠吃不到，`service-paths` 對明知有衝突的 monitor 仍蓋章 `pass`；現在把 `unknown` guard 移到兩個 systemd-effective 分支之前，任一邊判定 `unknown` 一律讓 `service-paths` fail，不再蓋章通過。
