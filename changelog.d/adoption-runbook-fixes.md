### Fixed

- **#1282 legacy adoption 實機缺陷修正：installer 自行處理、在審核階段（S2）就揭露**：參考主機第一次 legacy adoption（#1122）照 runbook 執行時遇到的六項缺陷，依 owner 原則（#1283：高信任自主工具，能自動判定與安全 quarantine 的就不加人工步驟；不刪 legacy 物件、真正有歧義才 fail closed）逐項處理。
  - **root installer 的 PATH 缺 `/usr/sbin`**：`useradd`／`groupadd` 改與 `visudo`／`cvtsudoers` 一樣只從固定系統目錄（`/usr/sbin`、`/usr/bin`、`/sbin`、`/bin`）解析、不看 PATH，兩者都在第一個 mutation 前解析，缺一個就 fail closed、不會留下半建的群組。runbook `trust-root-transactional-install.md` §1 `cortex_root_cli` 與 §3 apply 的 PATH 改為 `<venv>/bin:/usr/sbin:/usr/bin:/sbin:/bin`（與 `cortex upgrade` 相同）。§6 recover 的 PATH 留給 #1270 一併改寫；installer 不再依賴 PATH 找 sbin 工具，功能上已涵蓋。
  - **服務在 lease 前已停時 trap 誤判**：§3 以 `print(*[], sep="\n")` 產生服務清單，空清單仍印出一個換行，`mapfile` 讀成一個空字串，`cortex_restore_active` 對它 `systemctl start ""` 失敗，trap 因此保留 snapshot／marker。改為每個名稱一行、空清單不輸出；新測試直接以 bash 執行 runbook 裡的那幾行（`sudo` 換成記錄器），涵蓋空清單與一般清單。
  - **census 要求列出即將被 quarantine 的路徑**：plan 與 apply gate 把落在本 plan quarantine 物件內（含該物件本身）的 job 可寫路徑視為已涵蓋——apply 後該物件已不在原位、legacy 權限隨它進入 root-only 的 quarantine，`quarantine-then-create` 路徑則以 plan 權限重建；在 quarantine 物件「之上」的可寫路徑照舊需要 `census_exceptions`。
  - **socket／FIFO 在 apply 才失敗**：quarantine 的樹 digest 改為接受特殊檔：socket、FIFO 只記 type 與 mode，裝置節點另記裝置號，從不開啟；頂層殘留的 socket／FIFO 也可 quarantine（以 type／owner／mode／inode 綁定），purge 照 manifest 驗證後 unlink。只含檔案、目錄、symlink 的樹 digest 不變，既有 receipt 的 identity 照舊可驗。頂層裝置節點不是 cortex state，plan 仍以 `unclassified` 拒絕。
  - **無分類規則的 HOME 頂層檔案**：cortex 帳號 HOME 頂層 plan 未宣告的項目（shell history、`retry-*.json` 等）新增 disposition reason `home-top`，自動 quarantine；operator 列入 `quarantine_paths` 的照舊記為 `operator`。
  - **S2 審核看不到 plan 結論與 sudoers**：root capture（`legacy inventory`）在寫出 inventory 後，以 plan 的同一套推導產生 `plan_preview`（`ready`、`failures` 逐條含處置、quarantine 數與 summary；overlay 已有 `legacy_adoption` 區塊時沿用其清單），並以 apply preflight 的同一判定回報 `cortex_account_universal_nopasswd`（非 root 讀不到 sudoers）；兩者有問題時另寫 stderr，capture 本身照樣成功。runbook `trust-root-legacy-adoption.md` §0／§3 補上以 sudo 唯讀執行的前置檢查與審核方式，§1／§4 說明自動涵蓋的範圍。
  - **RC `legacy-adoption` profile**：harness 以絕對路徑、PATH 只有 installer 所在目錄與 `/usr/bin:/bin`（沒有任何 sbin）呼叫 installer，並要求 capture 的 `plan_preview` 在沒有任何 operator 清單時就 ready、sudoers 判定乾淨；fixture 拿掉 review-sandboxes 的 census 例外，新增 state 頂層與被 quarantine 目錄內的殘留 socket、FIFO，以及 Manager HOME 頂層的 retry 檔，rollback 照舊要求 inventory digest 完全還原。
  - openspec `trust-root-legacy-adoption` 的 spec／design 同步這些 disposition 與 census 規則。
