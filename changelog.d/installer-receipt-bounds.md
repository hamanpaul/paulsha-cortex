- transactional installer 的 receipt 與 rollback 修正四項既有限制（#1123）：
  - **目錄快照與子孫數量脫鉤**：目錄狀態只記 `children_count`／`children_sha256`，完整子孫清單改存 receipt 旁 root-only、content-addressed、不可覆寫的旁檔（`.<receipt>.inventory/<sha256>.json`，O_NOFOLLOW＋fsync＋原子 no-replace rename），在 prepared entry 落盤前寫入；rollback 讀取時以 digest 驗證，旁檔缺失、被竄改、被換成 symlink 或目錄權限不再是 root-only 時整個目錄列為 retained unknown（rollback-blocked），不據以分類或刪除任何東西。舊 receipt 的內嵌 `children` 仍可讀，載入時轉成 digest 形式並於下一次 checkpoint 前補寫旁檔；但位於受管目錄內的舊 receipt 不建立旁檔，磁碟上維持內嵌 `children`（僅在記憶體以 digest 比對），避免旁檔成為該目錄的 unknown state 而讓 rollback blocked。receipt 放在受管目錄內（會讓旁檔改動該目錄快照）時於 apply 變更前明確拒絕。receipt `schema_version` 升為 2（寫入一律 v2，載入接受 v1／v2），舊版 installer 讀到新 receipt 會以 `invalid receipt schema` 明確拒收，而非把非空受管目錄誤報為 unknown；`--prior-receipt` 仍可交接 v1 receipt。
  - **getfacl 加 `-E`**：mask 較嚴時不再把 `\t#effective:---` 解析進 perms，解析時也剝除 `#` 之後的註解，避免誤判 drift 與 rollback `setfacl -m` 失敗。
  - **rollback 後 `systemctl daemon-reload`**：rollback 還原或移除任何 systemd unit／drop-in 前先在 receipt 落下 `systemd_reload_pending`，結束時執行一次 daemon-reload，結果記於 rollback 報告與 receipt 的 `systemd_daemon_reload`；reload 失敗以 `systemd:daemon-reload` retained drift 回報並維持 rollback-blocked，下次 rollback 重試；中途崩潰後續跑也會補 reload。
  - **大檔／symlink 事前檢查**：preflight 對超過 1 MiB 的既有受管檔回報 `asset_prior_too_large`（附路徑、大小、上限與處置），對所有非 symlink 資產路徑上的 symlink 一次列出並拒絕；snapshot 讀舊內容改走有上限的 no-follow descriptor，不再把數百 MB base64 塞進 receipt。
