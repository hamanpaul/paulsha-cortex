- #841 loaded runtime attestation live 驗收修正：`systemctl --user show` 的輸出依 systemd 內部順序排列，`Id=` 位於區塊中間；parser 改為先以空行切區塊再找 Id，不再丟掉排在 Id 前面的 ExecStart／Environment／EnvironmentFiles／WorkingDirectory（真實 service 先前因此永遠被判成 `environment_source=unknown`、讀不到 loaded receipt）；多值的 `EnvironmentFiles`（每個檔案一行）改為串接，其他鍵重複仍標 malformed。
- #841 loaded runtime attestation 後續修法（invocation revision 對不起來）：manager 的 `invocation_revision` 改成以 daemon 實際收到的原始 argv token 計算（沿用 `_safe_config` 的機敏鍵過濾規則擋掉可能的機敏旗標值），不再用 `parse_args` 後的 namespace——namespace 對未指定旗標一律套用「可能受環境變數影響」的預設值，這些值已經由 `environment_revision` 涵蓋一次，用它算 `invocation_revision` 會讓宣告端永遠重放不出來，導致任何部署的 manager 都卡在 `invocation-declaration-unknown`（live 實測：user 級 pin 部署確認，monitor 不受影響因為它不記錄這個 component）。`cortex service status` 端新增 `manager_declared_invocation_revision`，在 `environment_source=systemd-effective` 時從 systemd 有效 `ExecStart` 反推同一份 argv，支援兩種目前會出現的形狀：(1) 直接呼叫 `python -m paulsha_cortex.coordinator.manager_daemon <args...>`；(2) installer 實際產生的 `/usr/bin/env bash <pkg>/scripts/service-manager.sh` wrapper——daemon 的 module 呼叫發生在腳本內的背景子行程，ExecStart 本身看不到，但腳本固定只傳 `--specs-dir`，值可由有效環境的 `PSC_MANAGER_SPECS_DIR` 精確重建；未宣告該變數時（預設值取決於 `$HOME`，不在安全允許清單內）維持回傳 `None`，不臆測家目錄。`compare_runtime_state` 同步新增「宣告值與 receipt 值不相等」時的 `invocation-drift` 判定（先前只處理宣告端為 `None` 的 unknown 情境，缺少真正的 drift 分支）。跨版本注意：舊 receipt（以解析後 namespace 算的 invocation_revision）與新宣告比對會落在 drift 或 unknown，manager 重啟寫入新 receipt 後即恢復 match，屬預期行為。
