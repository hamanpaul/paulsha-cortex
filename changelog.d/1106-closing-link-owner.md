- **`#1106` github_closing 不再牽連已有 owner 的票**：`correlate_work_sources()` 處理 `github_closing`（PR 關閉多張票）時，先前無條件把「整合 PR 關閉的第一張票（primary）目前的 owner」套用到 PR 本身與其餘每一張被關閉的票；其餘票若早就有自己的 override／frontmatter 歸屬，就會同時落在兩個群組，變成 confirmed source collision，讓整個 repo 被標 degraded（`auto_claim`／`merge` hard gate 全關）。live 案例：整合 PR `#1087`／`#1090` 各自關閉多張已有 work item 的票，目前只能靠 `.cortex/work-items.yaml` 逐一 `excludes` 才沒有 degraded。現在改為：來源若已有自己、與 primary 不同的權威歸屬（override／frontmatter／workflow_metadata），維持它自己的歸屬，不再套用 primary 的 owner；PR 本身的歸屬仍是確定性規則——沒有自己的 owner 時加入 primary 目前的 owner 群組（primary 也沒 owner 就一起落入 primary 的 `issue:<ref>` fallback 群組）。真正的衝突（同一票被兩個 override 明列）不受影響，仍回報 collision、仍 degraded。collision 目前仍是整個 repo 的 hard gate（未縮小為群組層級），評估後判定改動範圍過大，本次不處理。新增 `tests/test_correlation_integration_pr_closing_1106.py`，並以目前 repo 實際 `.cortex/work-items.yaml` 重建 PR `#1087`／`#1090` 的 closing 形狀驗證相容。
