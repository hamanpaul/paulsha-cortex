- **#1259 archive 與交付 PR 之後的 retry-build 派得出 Builder**：修正 OpenSpec archive 後 `retry-build` 必定被 `builder-todo-authority-changed` 擋下的問題。共有兩個阻斷點。第一，Manager archive 把本 run 的 mapped OpenSpec 從 active 推到 archived，WorkAuthority digest 因此前進；現在只有在本 run 有 Manager-owned 的 `openspec-archive` step，而且 registry 有唯一一筆 Manager archive job（`subject_head` 是 Candidate 本身或祖先）時，才把它還原成 claim-era 的 active 值再比對。第二，retry-build reset 把 run 推回 build 並清掉 `verified_head`，原本只在 review／ship 成立的交付 PR 例外隨之失效；現在要求三項證據同時成立：本輪 retry-build receipt 綁定 exact Candidate、delivery journal 證實這個 PR 由本 run 推送（每筆 push 都是 Candidate 本身或祖先）、authority 與 `run.pr_refs` 都恰為同一個 open PR。其他 links、issue 映射與 PR 狀態檢查不放寬。retry-build 的 admission（action 與 projection）改用與 Builder 派工入口相同的判定，並以 reset 後的 run 形狀評估：派不出 Builder 時在 reset 前就拒絕。新增 Manager-owned 的 `cortex-retry-build-receipt/v1`（`evidence/retry-build/<run_id>-<sha256>.json`，欄位為 schema、repo、work_id、run_id、claim_key、source_revision、expected_candidate、build_attempt、pr_refs）：它只供 Builder admission 判定，不會注入 prompt；reset 失敗時殘留的 receipt 綁的是 attempt N+1，不會讓 attempt N 的 run 放行（#1259）。
