### Fixed

- **Trust Root installer 只拒絕 cortex 帳號的免密碼 sudo，operator 的 NOPASSWD 放行**（Refs #1122）：owner 裁決（2026-10-06）cortex 定位為高信任自主開發工具，operator 帳號刻意保留 `<operator> ALL=(ALL) NOPASSWD: ALL`。原本 apply preflight 的 `universal_nopasswd` 只要 sudoers 有**任何**帳號的「萬用主機＋萬用指令＋免認證」規則就以 `universal NOPASSWD is forbidden` 拒絕，legacy adoption 因此得在 apply 期間把 operator 規則暫時移開，之後每次 `cortex upgrade` 也會被擋。
  - 改為 `backend._cortex_account_universal_nopasswd` 只看 plan 宣告的 cortex 帳號（`accounts` 的四個 principal 與 `service_accounts` 的 `cortex-egress`）：user-spec 以帳號名稱、`#uid`、帳號所屬的 primary／supplementary 群組（`%群組`、`%#gid`；uid／gid 以 plan 宣告為準併入主機現值，群組成員取 `gr_mem`，帳號尚未建立也涵蓋）、cvtsudoers `-e` 展開後含上述任一者的 User_Alias，或 `ALL` 指到它的萬用免認證規則才拒絕。名稱比對依 sudoers 預設 `case_insensitive_user`／`case_insensitive_group` 不分大小寫；runas 不縮小範圍（成為 root 是提權、成為另一個 cortex 帳號是跨 principal 橫移）；只對特定指令免認證照舊不算萬用。否定排除（`!帳號`）不採信、netgroup／non-Unix group 等本機證明不了成員的形式視為涵蓋——兩者都寧可多拒。
  - fact 改名 `cortex_account_universal_nopasswd`（`{"accounts": [...], "unproven": None | 原因}`），失敗代碼同名，detail 列出帳號（`universal NOPASSWD sudo is forbidden for cortex accounts: …`）。sudoers 狀態無法判定時照舊 fail closed，detail 寫明原因（`/etc/sudoers` 不是絕對路徑的 regular file、找不到 `visudo`／`cvtsudoers`、`visudo -c` 失敗、cvtsudoers 失敗或輸出不是合法 JSON），fact 形狀不對也 fail closed。`core.validate_preflight` 對舊 key `universal_nopasswd` 的 truthy 值照舊以原代碼拒絕；facts 不寫進 receipt，已安裝的 0.1.13 不讀它，receipt／plan 格式不變。operator 規則沒有既有的資訊欄位可放，不另記錄。
  - `visudo`／`cvtsudoers` 改從固定系統目錄（依序 `/usr/sbin`、`/usr/bin`、`/sbin`、`/bin`）解析，不再看 process PATH：9900X adoption 的 runbook PATH 沒有 `/usr/sbin`（Ubuntu 的 visudo 在那），舊實作因 `shutil.which` 找不到而誤報「universal NOPASSWD」。
  - 測試：cvtsudoers JSON fixture 覆蓋 operator 放行、`ALL` 拒絕、帳號名稱／`#uid`／primary 與 supplementary 群組／`%#gid`／User_Alias 拒絕、各種 runas、特定指令放行、全域 `Defaults !authenticate` 只作用在 cortex 規則、形狀錯誤 fail closed；真實 `visudo`／`cvtsudoers` 在 PATH 不含 sbin 下逐一驗證各 user-spec 形式（含 `!ALIAS` 展開翻轉否定）、host／command alias、include、include cycle 與語法錯誤 fail closed；假工具驗證只在固定目錄的工具照樣評估、PATH 上的同名工具不被採用、`visudo -c`／cvtsudoers 失敗與壞 JSON 都 fail closed；`validate_preflight` 驗證帳號列名、放行、unproven、壞形狀與舊 key 相容。
  - runbook `trust-root-transactional-install.md` §3 與 `trust-root-legacy-adoption.md` §0 補上這條 preflight 前提；`upgrade.py` 的 candidate PATH 註解改寫（`useradd`／`groupadd` 仍需 sbin）。
