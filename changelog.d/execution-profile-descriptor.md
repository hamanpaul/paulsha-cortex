- #835 refine 補齊：execution adapter descriptor 載入、Trust Root 接線、真 adapter conformance 與重啟語意。
  - **descriptor 資料化（AC1）**：adapter 的 protocol／runtime version、usage／quota 標籤、原生 effort 合法值、adapter 預設與 model 專屬預設，改由 packaged `paulsha_cortex/coordinator/data/execution-adapters.yaml`（schema v1）提供。`execution_adapters.py` 不再有寫死的 `_ADAPTERS` 表，launcher 的 `_VALID_REASONING_EFFORTS`、copilot／cg 預設與 codex 的 model→effort 對照也一併移除。`resolve_profile()`、`build_copilot_argv`／`build_codex_argv`／`build_cg_argv` 與 `validate_profile_for_launch()` 都透過 `ExecutionAdapter.launch_effort()` 讀同一份 descriptor；central resolver 的 `executor == "codex"` 分支已移除。
  - **operator overlay**：`$PSC_PROJECT_CONFIG_ROOT/execution-adapters.yaml` 用同一個 schema，同名 adapter 整筆取代 packaged 條目。overlay 依檔案 stat 熱讀；resolve 與 launch 之間若 descriptor 被改動，launch 前會拒絕。新增 model 或既有協定的 effort 只改 descriptor。
  - **fail-closed 驗證**：以下情況一律拒收，且不退回 packaged 預設：`schema_version` 缺少或不是 1、未知鍵、缺欄位、版本欄位不是字串、effort 值重複、`default`／`model_defaults` 不在 `values` 內、`quota_state` 不合法、descriptor 描述沒有受信任程式碼的 adapter、argv builder 沒有 `effort` 參數卻宣告 effort（claude／agy）。descriptor 錯誤屬部署設定錯誤：Manager 在建立任何候選／worktree／job 之前整次拒絕，不寫 per-run needs_human，修正後下一個 tick 自動恢復。已持久化的 binding 仍可載入。
  - **相容性**：內建五個 adapter 的 binding（descriptor＋三個 plane＋key）與寫死表時期逐位元組相同，由固定 digest 測試守住。既有 run 的 frozen binding、#842 qualification receipt 與 #844 stage-execution reuse key 不會因升級漂移。
  - **codex effort 通道**：`build_codex_argv` 新增 `effort` 參數，明示 effort 會發出 `model_reasoning_effort`（先前 codex launcher 的明示 effort 會被靜默忽略，profile 與 argv 可能不一致）。launcher 依 argv builder 的簽名傳入 `commit_required`／`effort`，沒有 effort 通道的 executor 帶 effort 時在建構期拒絕。
  - **新 runtime（AC2）**：`ExecutionAdapter` 新增 `argv_builder`／`usage_extractor` hook。`register_adapter()` 檢查受信任 argv 實作，以及 terminal／cancel／timeout 契約必須是 launcher 已實作的那一個；`SubprocessLauncher` 接受已登記的 runtime。conformance 測試改用虛構 runtime，以真 `ExecutionAdapter`＋`register_adapter` 走 `make_launcher_profile` → `validate_dispatch_requirements` → `SubprocessLauncher.launch()` 的 argv／spawn，並用 production 實作驗 terminal、usage、quota、cancel／timeout、工具與 sandbox；unsupported effort 或 executor 都是零 spawn。原本自證的 FakeAdapter 測試已移除。
  - **Trust Root 接線（AC3）**：`validate_dispatch_requirements()` 的 `trust_root_valid` 改為必填，並新增 `trust_root_reason`。新增 `trust_root_compatibility()`，以既有 `model_resolution` 相容性契約（加固 runner 下的 launcher profile＋toolchain／credential grant）判定。Manager workflow 派工與 slice lane（不看 capability，其餘照驗）都已接上。沒有 runtime 需求宣告的卡被拒絕時持久化 `execution-profile-blocked` needs_human，不再讓 `ValueError` 打穿 tick；有需求宣告的卡在 preflight gate 內是候選層級拒絕，理由指名 Trust Root。
  - **unknown role（#581）**：legacy manifest 的未知 persona 在候選選擇前，就以 `execution-profile-blocked` 持久化 needs_human，不會默認 build。
  - **重啟與 legacy manifest（AC5）**：新增由 #835 合併前 main 實際寫出的 registry fixture（`tests/fixtures/execution_profile/legacy-registry-pre-835.json`），測試涵蓋：legacy 欄位位元組不變、Manager 重啟（重新載入 registry 與 catalog）後 in-flight job 照舊沿用、retry-build 重派解析出同一 identity 與逐位元組相同的 binding。移除 `test_a5` 的恆真斷言，改為比對磁碟上的位元組。
  - 文件：`docs/execution-profile.md` 新增 descriptor 位置、schema、驗證與優先序，以及 Trust Root／unknown role／重啟語意；`docs/execution-profile-schema-core.md` 與 README 同步更新。
