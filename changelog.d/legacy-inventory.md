- transactional installer 新增 legacy adoption 的唯讀 inventory collector（#1122，PR-2）：
  - **`cortex install trust-root legacy inventory --config C [--host-overlay O] --bundle B --output P`**（需 root）：以 shared 方式取得 maintenance lock 與 host-global transaction lock，只讀不寫；主機已有 canonical receipt parent、maintenance snapshot 或 lease marker（含進行中的 lease）時拒絕並指向 `--prior-receipt`；輸出以 no-replace rename 寫成新檔（root 0644），既有路徑一律不覆寫。`--output` 在任何收集前檢查：不得落在 deploy／state／systemd／polkit roots、任何 plan 受管路徑或帳號 HOME 之下（既有祖先另以 inode 比對，bind mount 別名同樣拒絕），任一層不得是 symlink，錯誤訊息建議改用 installer 自有位置 `/var/lib/cortex-installer/legacy/`；`publish_inventory` 依 inventory 自身的 scope 再檢查一次。
  - **`cortex install trust-root legacy show --inventory P`**（不需 root）：驗證 schema 與自證 digest 後印出人可讀摘要（帳號 desired／observed 與 uid／gid 持有者、受管路徑、探索到的權威面／credential／其他物件、credential 目的地、service、可寫 census、不入 digest 的 gate 計數）。
  - **inventory schema v1**：canonical ASCII JSON，`inventory_sha256` 只涵蓋穩定欄位（`collector` 與 `volatile` 不入：擷取時間、hostname、active_state、in-flight、census 與 state 計數、owner census、目錄 entry 數）；`scope_sha256` 由 config＋overlay 推導的 roots、帳號名與 HOME、plan 受管路徑集合、credential 目的地、探索規則與 census 規則組成；host binding 為 domain-separated 的 machine-id SHA-256，不輸出原文。
  - **collector**：帳號（passwd、同名 group 與成員、supplementary、密碼鎖定、desired／observed uid／gid 持有者）；受管路徑 lstat＋ACL（`getfacl -cpE`）；依 verify 權威列舉規則探索 systemd `cortex*`（含 drop-in 內容）與 `*.wants`／`*.requires` 的 cortex 項、polkit `*cortex*`、env 目錄、deploy root 頂層、`toolchain/bin`、各帳號 HOME 頂層、state root 頂層，以及受管目錄內未列管的子目錄與暫存／備份殘留；三個 service 的 load／unit-file／fragment／drop-in／User／ExecStart。credential 類（adapter 目的地、`*.env`、`*oauth*` 等名稱、credential 目錄）只記 type／owner／mode／dev／ino，絕不開檔；超過 1 MiB 的檔與 symlink 只記 metadata／target。schema 驗證依路徑重新判定 credential 類，帶內容的 credential row 會被拒收；運轉中物件在 lstat 與讀取之間變動時重新觀察，消失則不記。
  - **writable census**：root 以不跟隨 symlink、逐層 `O_NOFOLLOW` 重開的方式列舉 state、deploy、systemd、polkit 與各 HOME，記下每個非 symlink 項目的 dev／ino；fork 出的子行程依序 `setgroups`→`setresgid`→`setresuid` 成各 job 帳號（builder、reviewer-planner、gate、egress，子行程不 exec，換身分後不可被 ptrace），再以該身分沿同一棵樹逐層 `openat(O_PATH|O_NOFOLLOW)` 並驗證 inode（traversal 由 kernel 以 job 身分判定），在已驗證的目錄 fd 上直接呼叫 `faccessat2(W_OK, AT_SYMLINK_NOFOLLOW)` syscall 判定可寫，前後各一次 no-follow `fstatat` 比對 inode／type。項目在列舉後或判定期間變成 symlink、inode 改變或消失時記為 `unstable`（census status 為 `unstable`，列在 inventory 並入 digest，CLI 輸出 `census_stable: false` 與警告，後續 plan／apply gate 必須拒收），不默默略過；落在該帳號自身宣告可寫區內的變動不計。kernel 不支援 `faccessat2`／`AT_SYMLINK_NOFOLLOW`（ENOSYS／EINVAL／ENOTSUP）時整個 census fail-closed 並給明確錯誤，不退回會跟隨 symlink 或忽略 ACL 的判定（刻意不用 `os.access(follow_symlinks=False)`：舊 kernel 上 glibc 會改以 mode bit 模擬而忽略 ACL）。輸出每個 principal 在 plan 宣告的可寫資產（permgen `writer_accounts`，`<job-id>` 視為單一路徑段，加上 desired owner／mode／ACL 給予寫入的受管路徑）以外的可寫路徑，可寫目錄只列最外層。
  - **`--host-overlay`**：只允許 `accounts.<name>.{uid,gid}`、`service_accounts.cortex-egress.{uid,gid,home}`、`operator_account`、`external_reader_account`、`providers.builder` 與 `legacy_adoption`，其他 key 一律失敗並點名；overlay digest 不含 `legacy_adoption`（該區塊綁定本 inventory digest）。本 PR 不改 plan 產生邏輯。
  - `plan` 指令改經共用的 `_bound_plan_from_config`，沒有使用新 CLI 時 release config 的 plan 與基底逐位元組相同（黃金 digest 回歸測試）。
